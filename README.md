# Hierarchical Recursive Causal Feature Selection for Explainable Schizophrenia Prediction from DNA Methylation

The project implements a hierarchical analytical framework integrating DNA methylation analysis, differentially methylated regions (DMRs) identification, statistical feature selection, machine learning (ML), SHAP-based feature selection, and hierarchical causal discovery for schizophrenia classification.

## Data

The analysis uses DNA methylation data together with sample metadata and epigenetic age acceleration (EAA) measurements.

The methylation datasets are represented using sample-level DMR matrices. Metadata and epigenetic age acceleration features are subsequently joined using `sample_id`.

The methylation measurements are based on the Illumina HumanMethylation450 BeadChip platform.

---

## Preprocessing

The preprocessing stage performs quality control and preparation of the CpG-level DNA methylation data for downstream analyses and computation.

The preprocessing workflow includes removal of:

- Sex-chromosome probes
- Multi-mapping probes
- Cross-reactive probes
- Other probes failing the predefined quality-control criteria

Beta values are transformed to M-values for downstream statistical analysis.

Batch effects are corrected using NeuroComBat.

---

## DMR Analysis

DMRs are identified from the processed methylation data.

DMR detection is performed using `DMRcate` together with the corresponding linear-model framework.

Statistical significance is controlled using the Benjamini-Hochberg procedure with:

```text
FDR < 0.05
```

The resulting DMR matrix forms the basis for subsequent feature-selection and classification analyses.

---

## DMR-to-Gene Mapping

DMRs are first mapped to genes using the 450K array manifest CpG probe annotations and subsequently through predefined transcription start site (TSS) region.

The mapping region used in the analysis is:

```text
TSS -2000 bp to +500 bp
```

Any remaining DMRs are mapped to genes on the basis of proximity.

The resulting DMR-to-gene relationships are used for subsequent gene-level and module-level analyses.

---

## Gene Ontology

Gene Ontology (GO) enrichment analysis is used to map the genes obtained to biological process terms. This set of terms is filtered using specific keywords with respect to their relevance to this study.

This acts as a intermediate refinement stage between the ME- and gene-level causal discoveries as well as a method to utilise domain knowledge as a feature selection criterion.

---

## WGCNA

Weighted Gene Co-expression Network Analysis (WGCNA) is used to identify groups of co-expressed genes.

The network construction uses a soft-thresholding power selected using the scale-free topology criterion.

The analysis uses:

```text
Scale-free topology R² ≥ 0.9
```

with a minimum module size of:

```text
30 genes
```

The resulting module eigengenes (MEs) are used as inputs to module-level causal discovery.

---

## Causal Discovery

Causal discovery is performed hierarchically.

### Module-Level Causal Discovery

MEs are first analysed to identify relationships between WGCNA modules, age, sex, and disease status.

The resulting causal structure is used to identify modules with potential direct relationships with disease.

### Gene-Level Causal Discovery

Genes associated with the selected modules are mapped back to their gene-level representations.

Feature reduction is performed before causal discovery using the predefined filtering and ranking procedures.

The resulting gene-level causal structure is used to identify candidate disease-associated genes.

### DMR-Level Causal Discovery

Genes identified at the gene level are mapped back to their associated DMRs.

Causal discovery is then performed at the DMR level to identify candidate methylation regions with direct relationships to disease.

---

## Causal Feature Selection

The hierarchical causal analysis progressively reduces the feature space:

```text
Module-level discovery
     │
     ▼
Selected modules
     │
     ▼
Gene mapping
     │
     ▼
Gene-level discovery
     │
     ▼
Selected genes
     │
     ▼
DMR mapping
     │
     ▼
Selected DMRs
```

The initial causal feature set obtained is `c0` which is then enhanced for prediction through the addition of the derived EAA variables, producing `c1`.

---

## Baseline Construction

The baseline-construction stage generates the statistical and SHAP-derived feature sets used for comparison with the final causal feature set.

The classification baselines are constructed from DMR features together with the appropriate metadata and epigenetic age acceleration covariates.

The baseline construction workflow includes:

1. Statistical baseline construction
    1. DMR variance filtering
    2. DMR correlation-network pruning
2. SHAP-based baseline construction
    1. Top-DMR selection by variance
    2. Logistic regression training
    3. Random forest training
    4. SHAP computation
    5. SHAP feature ranking
    6. Top feature selection by SHAP ranking

---

## SHAP-Based Feature Selection

SHAP values are computed independently for the logistic regression and random forest models.

For each model, features are ranked according to their mean absolute SHAP contribution.

The cumulative relative SHAP contribution is then used to select the features accounting for the predefined proportion of the total SHAP contribution.

The resulting feature sets are model-specific.

The SHAP-derived datasets are subsequently used for classification-performance comparison.

---

## Classification

The classification stage evaluates the different feature sets using two ML models:

- Logistic Regression
- Random Forest

Both models are trained using the training portion of each dataset.

Hyperparameter optimisation is performed using:

```text
5-fold StratifiedKFold cross-validation
```

with:

```text
shuffle = True
random_state = 42
```

ROC-AUC is used as the model-selection metric during hyperparameter optimisation.

### Logistic Regression

The logistic regression pipeline consists of:

```text
StandardScaler
      │
      ▼
LogisticRegression
```

Class imbalance is addressed using:

```text
class_weight = "balanced"
```

### Random Forest

The random forest classifier also uses:

```text
class_weight = "balanced"
```

---

## Classification Feature Sets

The classification analysis evaluates several feature configurations.

The principal dataset identifiers are:

| Dataset | Description |
|---|---|
| `c0` | Core causal set |
| `c1` | Final causal/integrated feature set (EAA values added to `c0`) |
| `s0` | Statistical baseline |
| `s1` | Model-specific SHAP-derived feature set |

Because SHAP selection is performed independently for each classification model, the `s1` datasets are represented internally as:

```text
s1_lr
s1_rf
```

where:

- `s1_lr` is the SHAP-selected dataset associated with logistic regression
- `s1_rf` is the SHAP-selected dataset associated with random forest

For reporting purposes, both are referred to as `s1`.

---

## Classification Evaluation

Classification performance is evaluated on the corresponding held-out test dataset for each trained model.

The evaluation metrics are:

* Accuracy
* Precision
* Recall
* F1 score
* F2 score
* ROC-AUC

Each model is evaluated only on the test dataset corresponding to its training feature configuration.

Trained models are saved under:

```text
results/classification_performance/models/
```

Classification-performance results are saved under:

```text
results/classification_performance/performance_metrics/
```

---

## Bootstrap Metric Comparison

Pairwise classification-performance comparisons are performed using bootstrap resampling.

The comparisons evaluate:


* `c0` vs. `c1`
* `c1` vs. `s0`
* `c1` vs. `s1`


for both logistic regression and random forest.

The comparisons are performed using paired bootstrap samples of the same test observations.

For each dataset comparison pair, (D1, D2), and metric, M, the bootstrap distribution of:

```text
M(D2) - M(D1)
```

is calculated.

The 95% confidence interval is obtained from the:

```text
2.5th percentile
97.5th percentile
```

of the bootstrap distribution.

The resulting comparison table contains:

```text
dataset_comparison_pair
model
accuracy_ci
precision_ci
recall_ci
f1_score_ci
f2_score_ci
roc_auc_ci
```
